### Задание 1

На лекции рассматривались режимы репликации master-slave, master-master, опишите их различия.

Ответить в свободной форме.

### Решение 1

Master-Slave репликация
В этом режиме один сервер играет роль мастера, а второй — слейва. Все операции записи (INSERT, UPDATE, DELETE) выполняются только на мастере. Слейв получает копию этих изменений и применяет их у себя. Чтение данных можно распределять между мастером и слейвом, но запись — строго на мастер.

Плюсы:

Простая настройка и сопровождение.
Возможность масштабировать чтение.
Подходит для резервного копирования и анализа данных.

Минусы:

Мастер — единственная точка записи: при его сбое запись невозможна.
Репликация идёт с небольшой задержкой.

🔹 Master-Master репликация
Здесь оба сервера являются равноправными мастерами и могут принимать как запись, так и чтение. Изменения на одном сервере реплицируются на другой и наоборот. Такой режим требует более сложной настройки.

Плюсы:
Возможна запись на оба сервера — удобно для распределённых систем.
Повышенная отказоустойчивость (если один мастер вышел из строя, другой продолжает работу).
Упрощённый переход между активным и резервным сервером.

Минусы:

Возможны конфликты данных, если одна и та же строка редактируется на разных мастерах.
Требует синхронизации автоинкрементов (например, настройка разных шагов или чётности).
Более сложная конфигурация и сопровождение.


### Задание 2

Выполните конфигурацию master-slave репликации, примером можно пользоваться из лекции.
Приложите скриншоты конфигурации, выполнения работы: состояния и режимы работы серверов.


### Решение 2


Конфигурационные файлы
master.cnf

ini
```
[mysqld]
server-id=1
log_bin=mysql-bin
```
slave.cnf
```
ini

[mysqld]
server-id=2
relay-log=relay-log
read_only=1
```

Создаем Docker-сеть

docker network create mysql-net


Запускаем контейнеры master и slave

Master:

docker run -d --name mysql-master \
  --network mysql-net \
  -p 3307:3306 \
  -v ~/mysql-replication/master.cnf:/etc/mysql/conf.d/master.cnf \
  -e MYSQL_ROOT_PASSWORD=root \
  mysql:8.0

Slave:

docker run -d --name mysql-slave \
  --network mysql-net \
  -p 3308:3306 \
  -v ~/mysql-replication/slave.cnf:/etc/mysql/conf.d/slave.cnf \
  -e MYSQL_ROOT_PASSWORD=root \
  mysql:8.0


Проверяем

docker ps

начальная настройка master

docker exec -it mysql-master mysql -uroot -proot

Создание базы, таблицы и пользователя репликации:

sql
CREATE DATABASE test_db;
USE test_db;
CREATE TABLE test_table (
  id INT PRIMARY KEY,
  message VARCHAR(255)
);
INSERT INTO test_table VALUES (1, 'Hello from Master');

CREATE USER 'replica_user'@'%' IDENTIFIED WITH mysql_native_password BY 'replica_pass';
GRANT REPLICATION SLAVE ON *.* TO 'replica_user'@'%';
FLUSH PRIVILEGES;
FLUSH TABLES WITH READ LOCK;


Получение координат лога:

sql

SHOW MASTER STATUS;

| File             | Position |
|------------------|----------|
| mysql-bin.000003 |     843 |

 
Настраиваем slave

docker exec -it mysql-slave mysql -uroot -proot
Установка параметров репликации:

sql

CHANGE REPLICATION SOURCE TO
  SOURCE_HOST = 'mysql-master',
  SOURCE_PORT = 3306,
  SOURCE_USER = 'replica_user',
  SOURCE_PASSWORD = 'replica_pass',
  SOURCE_LOG_FILE = 'mysql-bin.000003',
  SOURCE_LOG_POS = 1619;

START REPLICA;
